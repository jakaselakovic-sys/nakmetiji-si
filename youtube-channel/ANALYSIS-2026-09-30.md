# Channel analysis: "How money actually worked" (30 Sep 2026)

**Based on:** `CLAUDE.md`, `HANDOFF-PROMPT.md` and the `youtube-growth-engine` skill. I have **not** seen the code, the video or the other docs. A **[verify]** mark means the Claude Code session on the PC has to confirm the point against the code or data.

**Goal:** a fully automated channel with strong engagement and good CPM, whose episodes can be repeated at high quality, never AI slop.

---

## 1. Verdict

- **Quality and compliance:** the foundation is unusually strong. The rules (rights ledger, fact gates, `fixes.json`, the master gate, edit-as-data) are what most faceless channels lack.
- **Weakest point: repeatability.** Episode 1 is a hand-built film.
  - 98 shots were placed by hand in `edit_film.py`.
  - The diagrams were made for this one story (tally, chequer board, notch scale).
  - The planned v2 adds even more one-off work: 45 hand-placed sound effects, 31 per-picture effect settings, 5 custom reconstructions.
  - If episode 2 needs the same effort, the channel can't hold a weekly schedule. The inauthentic-content risk goes *up* when a rushed schedule forces shortcuts.
- **The fix:** spend every v2 hour on **reusable machinery**, not episode-1 polish. The acceptance test is simple: episode 2 must be built mostly from components episode 1 created.

## 2. What's strong: keep it

| Strength | Why it matters |
|---|---|
| Edit-as-data (`edit_film.py` → JSON), cues on spoken words | Re-cuts, Shorts and re-voicing don't break the timing. This is the core of automation. |
| Word-level ASR timings + fuzzy cue matching that fails loudly (exit 2) | A missing sync point is caught at build time, not in a viewer's comment. |
| Three gates (script / edit / master) with measured thresholds | Quality is a number, not a feeling. That's the only way to scale without slop. |
| `fixes.json` enforcing fact-check wording | Fact-check fixes can't regress when the script is edited. |
| `rights.json` before placement + credits generated from it | Protects monetisation, and the credits are free. |
| Real scanned documents with OCR highlights | The best anti-slop signal the channel has: primary sources on screen. Competitors rarely do it. |
| Braided structure (the fire returns between acts) + a "today" payoff | Open loops for retention; the "today" part tilts the audience toward finance advertisers (CPM). |
| One voice, one scene template, one renderer | Simple, and consistent brand identity. |
| Lessons-learned list (§5) | Written-down failure modes stop repeated mistakes across sessions. |
| Four human checkpoints (topic, read-aloud, watch, Public) | The right places for human judgement. Everything between them is machine work. |

## 4. The main fix: an episode factory (repeatable, not sloppy)

**The principle.** Slop comes from *generic* content: stock montage, AI images, a voice reading Wikipedia. Hand-crafting everything doesn't prevent it. This channel's quality comes from **specific sources** (real paintings, real document scans, real quotes) and **mechanism diagrams**. Both can be automated if the *components* are generic and the *content* is specific.

### 4.1 Pipeline per episode (target: most steps are machine work)

| Stage | Machine does | Human | Output |
|---|---|---|---|
| 1. Topic | Scores the backlog: search demand, outlier formats in the niche, CPM angle, "is there something to show?" | **H1: pick** | `brief.md` |
| 2. Research | Pulls sources (Wikipedia is only a map to primary sources; Internet Archive / HathiTrust / Google Books PD scans; museum open-access APIs), builds a claims ledger with page references | – | `dossier.md`, `claims.json` |
| 3. Script | Writes the braided structure against the retention rules (hook ≤ 5 s, question ≤ 15 s, today-stake ≤ 30 s, re-hook every 60–90 s, sentences ≤ 22 words, 150–165 wpm), with a `claims` id on every line | **H2: read aloud** | `script.json` |
| 4. Adversarial fact check | A subagent attacks every claim → fixes go into `fixes.json` | – | `FACT-CHECK.md` |
| 5. Assets | Searches Commons / museum APIs **with licence filters in the API call**; writes `rights.json` rows from the API metadata automatically; saves terms snapshots | – | `a/`, `rights.json` |
| 6. Voice + ASR | Kokoro → sherpa-onnx timings; flags lines with word error > 12% | – | `voice/` |
| 7. **Auto shot plan** (new) | Maps each script segment to a **shot recipe** (see 4.2) using asset tags + claim types; writes a *draft* edit file | Optional polish | `edit-film.json` |
| 8. Sound effects (new) | Suggests effects from cue words using a tagged library (see 4.3); enforces density and "never on a stressed word" | – | `sfx` events |
| 9. Render + gates | Everything in the current pipeline + the new gates (4.4) | – | `master.mp4`, gate JSONs |
| 10. Packaging | Titles, description, chapters, thumbnails, Shorts cuts | **H3: watch**, pick thumbnail | `final/` |
| 11. Publish | – | **H4: Private → Content ID → Public** | – |

### 4.2 A shot-recipe library (the key new component)

The edit becomes *mostly generated*: each segment gets one of ~12 recipes, each a parameterised template in `scene.html` + `plate.py`:

| Recipe | Used for | Motion source |
|---|---|---|
| `painting-plate` | an identified painting or print | depth parallax + an effect chosen from **tags** (fire, water, fog, dust) |
| `portrait-plate` | named people | gentle parallax + light sweep + name chip |
| `document-highlight` | quotes from primary sources | page tilt + OCR highlight + quill SFX |
| `map-event` | where something happened | pins, poly, an animated front/route |
| `timeline-jump` | dates, eras | rail + year count-up |
| `stat-reveal` | the number that matters | `big` count-up on a textured ground (never a plain one) |
| `mechanism` | how a thing worked | reusable parts: **object-split, cross-section, flow-arrows, ledger/counting board, stack/weigh** |
| `object-closeup` | coins, sticks, notes | a museum photo + parallax + macro sweep |
| `footage-cutaway` | present-day places, textures | real footage ≤ 15 s, narrated over, never labelled as the historical event |
| `today-screen` | the "your life now" section | a generic fictional app UI, no real brands |
| `quote-card` | secondary quotes | a paper ground + ink type |
| `match-cut` | act transitions | shape/colour match between two recipes |

**Why this fixes repeatability:** ep1's "tally split" becomes `mechanism: object-split`, and ep2 reuses it for the copper plate stamping. The ep1 fire front becomes `map-event: spreading front`, which ep2 reuses for a bank run spreading through Stockholm. Per-episode work shrinks to choosing recipes and checking them.

**The rule for v2 work:** build nothing that only ep1 can use. Every ep1 reconstruction is built as a recipe with parameters.

### 4.3 Sound effects without hand-placing 45 events per episode

- One **tagged SFX library** (Sonniss + synthesised): `{file, tags:[cut, wood, knife], licence}`.
- A **cue→tag map**: the words "cut / notch / carved" suggest `cut+wood`; "fire / flames / burned" suggest a fire bed; count-ups get ticks; highlights get the quill.
- The machine places the suggestions, then enforces the rules:
  - one event per 12–15 s on average, and at most one per 5 s;
  - −8 to −20 dB relative to the voice;
  - never on a stressed word (use the ASR word energy);
  - never a "fact" sound (bells, crowds, voices).
- **A human only vetoes; they never place.**

### 4.4 New gates (quality stays a number as volume grows)

Add these to `check.py`. Numbers come from the handoff targets where one exists:

- **edit:**
  - plain-ground shots ≤ 8;
  - any one picture ≤ 5 uses;
  - third-party footage ≤ 15% of runtime, clips ≤ 15 s, never the opening shot;
  - in-picture motion ≥ 85% of runtime;
  - SFX density within limits.
- **script:**
  - hook question by 0:15;
  - today-stake by 0:30;
  - no sentence > 22 words;
  - 150–165 wpm;
  - every line carries a claim id or is marked `opinion/transition`;
  - the ending names the next episode.
- **rights:**
  - every asset used in the edit has a ledger row;
  - no blocked licence or source;
  - terms snapshot present for Pexels and YouTube-sourced clips;
  - YouTube-sourced runtime share is reported (the new rule says it "must never make up most of the episode").
- **packaging:**
  - title 45–60 characters;
  - thumbnail readable at 120 px (automate it: downscale + OCR it back);
  - thumbnail words ≠ title words;
  - chapters match `resolved.json`.

### 4.5 Measure the factory itself

Log per episode in `performance.jsonl`: **human minutes per checkpoint**, machine render hours, gate failures, fact-check issues found. The target to verify, not a promise: ≤ 3 h of human time per episode by episode 5. If an episode needs more, the log shows which stage to automate next.

## 5. Engagement and CPM

1. **CPM positioning is good. Lean into it deliberately.**
   - History audiences earn lower CPMs than personal-finance audiences; the "today" section bridges the two.
   - Put a concrete finance noun in **every** title or thumbnail pair: money, bank, debt, inflation, interest, savings, credit.
   - Make the today-section substantive (≥ 60–90 s): it's what finance advertisers target and what makes the video useful. **[verify]** its current length in ep1.
2. **Series packaging.**
   - A consistent title shape for the series (e.g. "*The X That Y*") and a consistent thumbnail system (the accent colour, the same type, one object).
   - This builds recognition in browse. Test the *topic* and keep the *frame* constant.
3. **The first 30 seconds decide everything.**
   - Add an automated **hook audit**: the cold open must show the thumbnail's promise within 5 s (title/thumbnail ↔ the first 90 s must match).
   - After publishing, read retention at 30 s. If it's < 65%, the hook is the first thing to change in ep2.
4. **Mid-rolls.** Three breaks in 10:05 is fine. Keep them at act breaks after an open loop ("…but that's not what burned the building"). Viewers come back after an ad to close a loop.
5. **Session watch time.**
   - The ending promises ep2. So ep2 must go **live by the time ep1 has been up a week** (22 Oct), or that end screen points nowhere.
   - Use a series playlist as the end-screen target until ep2 is live.
6. **Shorts as a feeder from ep1.** Two per episode, rendered vertically from the same edit data (a recipe `aspect: 9:16` switch, not a crop). Publish on the off days.
   - The best Shorts material in ep1: the tally split (a visual payoff) and "wooden receipts burned Parliament" (a one-line hook).
7. **Comments.** Pin a specific question that the viewer's own life answers (e.g. "What's the oldest form of money you've actually held?"). Replies in the first 2 hours help ranking.
8. **Test & compare:** keep the three thumbnails. Change **one** packaging variable per video and log it in `experiments.md` (no learning from ep1 alone; rules need ≥ 8 videos).
9. **Localisation later.** Auto-dubbing unlocks around 1,000 subscribers. Leave room in the plan, but don't spend on it now.

## 6. Quality: staying clear of slop as the channel scales

- **Keep the bans:** no AI images or video, no stock standing in for history, no presenter avatar. These are the channel's moat.
- **Primary sources on screen** (document highlights) in **≥ 3 shots per episode**: make it a gate.
- **Picture variety:** ≤ 5 uses per picture. A reuse-heavy edit is the most visible "cheap" signal.
- **Voice:** Kokoro is good, but TTS fatigue sets in over 10 minutes.
  - Per-act speed is already there. Add **automatic pauses** after key reveals (a punctuation → silence map) and vary sentence length.
  - The H2 read-aloud should listen specifically for flat reveals.
- **Mechanism > decoration.** Every reconstruction must explain *how* something worked (the furnace flue is the model). An effect with no explanatory job gets cut.
- **Each episode argues something.** Every episode needs one line stating what the episode claims that no single source says. It keeps the channel on the right side of YouTube's "reused/inauthentic content" line more reliably than any visual trick.

## 7. Automation and operations

- **Where it runs:** the PC for rendering and downloads; GitHub Actions (private repo, about 2 min/week) for the weekly analytics pull and the backlog scoring. It needs the repo on GitHub (§3.4). Keep the "commit even when nothing changed" step: GitHub disables scheduled workflows after 60 days with no repository activity.
- **Analytics:** YouTube Analytics API with OAuth. You do a one-time 20-minute Google Cloud setup, and everything after it is scripted. Before the Partner Program, revenue metrics return nothing; that's expected.
- **The learning loop:** the phases are right (videos 1–8 packaging only, 9–20 one parameter at a time, 20+ monthly rule rewrites). Don't write a rule from fewer than 8 videos.
- **Upload stays manual** (the Content ID check, and API quota). That's correct, not a gap.
- **Keep it simple:** no new frameworks. The additions are the recipe library, the SFX library + map, `preflight.py`, the new gates and `analytics`. Each is one file or folder.
